PROBLÈMES RENCONTRÉS
--------------------------------------------------------------------------------
P1  Erreur   : binaire blink.cmp laissé en « libblink_cmp_fuzzy.dylib.tmp »
              après `nvim --headless "+Lazy! sync" +qa`.
    Cause    : le téléchargement du binaire est asynchrone ; +qa a quitté
              Neovim avant la fin.
    Solution : suppression du .tmp et téléchargement synchrone, puis
              vérification du SHA-256 (ceeae0c3…a36945, identique au .sha256
              officiel).
    Commande : nvim --headless -c 'lua require("lazy").load({plugins={"blink.cmp"}});
              local d=false; require("blink.cmp.fuzzy.download")
              .ensure_downloaded(function(e) d=true end);
              vim.wait(100000,function() return d end)' -c qa

P2  Erreur   : :checkhealth vim.pack -> WARNING « Lockfile is absent, plugin
              directory is present » (dossier site/pack/core/opt recréé vide
              alors qu'il avait été supprimé).
    Cause    : catppuccin v2 active par défaut `auto_integrations`, qui
              appelle vim.pack.get() pour détecter les plugins ; cet appel
              crée le dossier de vim.pack (runtime/lua/vim/pack.lua l.872).
    Solution : auto_integrations = false + liste explicite des intégrations
              (blink_cmp, gitsigns, neotree, telescope, which_key).
    Commande : rm -rf ~/.local/share/nvim/site/pack ; édition de
              lua/plugins/colorscheme.lua

P3  Erreur   : :checkhealth vim.lsp -> WARNING « buffers attached to multiple
              clients with different position encodings » (UTF-16 / UTF-8).
    Cause    : sur un fichier Python, basedpyright choisit UTF-16 et ruff UTF-8.
    Solution : vim.lsp.config("ruff", { capabilities = { general = {
              positionEncodings = { "utf-16" } } } })

P4  Erreur   : :checkhealth vim.lsp -> WARNING « Unknown filetype 'c.doxygen' /
              'cpp.doxygen' ».
    Cause    : la config clangd de nvim-lspconfig liste ces filetypes que
              Neovim 0.12.5 ne connaît pas.
    Solution : vim.lsp.config("clangd", { filetypes = { "c", "cpp", "objc",
              "objcpp", "cuda" } })

P5  Erreur   : :checkhealth provider -> WARNINGS node/perl/ruby/python
              (« neovim » npm absent, Neovim::Ext absent…).
    Cause    : providers de plugins distants actifs mais non utilisés.
    Solution : vim.g.loaded_{python3,node,perl,ruby}_provider = 0

P6  Erreur   : :checkhealth lazy -> ERROR luarocks not installed (config initiale).
    Cause    : lazy.nvim active le support luarocks par défaut.
    Solution : rocks = { enabled = false } (aucun plugin n'en a besoin).

P7  Échecs de MES scripts de test (pas de la config) :
    - « attempt to index local 'picker' (a nil value) » / « Invalid window id »
      : mon script fermait Telescope sur le mauvais buffer -> corrigé.
    - Ctrl+P, which-key et lualine « non testables » en --headless : le stub
      `keys` de lazy.nvim renvoie les touches de façon asynchrone et
      l'événement VeryLazy dépend de l'interface. -> Tests refaits dans un
      vrai terminal (pty Python + socket RPC) : tous OK.

Avertissement restant, NON corrigeable et sans conséquence :
  blink.cmp health : « Some providers may show up as "disabled" but are
  enabled dynamically » -> message codé en dur (health.lua l.52), toujours
  affiché, purement informatif.
